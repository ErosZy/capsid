# Capsid v0.2.0-rc.07

This release candidate focuses on deterministic request cleanup, reliable
release installation, and restoring the benchmark evidence pipeline. It also
tightens resource and CORS configuration boundaries discovered during the
rc.06 review.

## Highlights

- Request-terminal cleanup now uses a non-extendable budget owned by each
  request. User-created Promise reactions parked on timers are treated as
  detached work, while the runtime's already-queued completion jobs can still
  unwind normally. Terminal JavaScript execution also has an independent CPU
  bound.
- The A/B benchmark evidence generator is restored. The runner and fake
  gateway now reap components on successful runs and on every early error
  path, preventing one run from affecting the next.
- `install.sh` now stages and validates a package before activation, supports
  native Windows `.exe` names, updates all commands on upgrade, handles
  relative prefixes correctly, and fails if any required tool is absent.
- Static pools accept 1..4096 workers. Larger values and allocation failures
  return an operator-facing startup error instead of terminating the Host.
- Listener CORS uses the complete HTTP token grammar, matches origin
  scheme/host case-insensitively, rejects mixed wildcard/exact origin lists,
  and emits `Vary: Origin` consistently on origin-dependent responses.
- musl package dependency checks and fresh reproducibility builds now inherit
  the effective libc and Boost configuration used by the baseline build.

## Installation

Linux packages are x86_64 static-musl archives, macOS packages are arm64, and
Windows packages are x86_64 ZIP archives with the static CRT.

```sh
curl -fsSL \
  https://github.com/ErosZy/capsid/releases/download/v0.2.0-rc.07/install.sh \
  | bash -s -- v0.2.0-rc.07
```

Set `PREFIX=/custom/path` or pass `--prefix /custom/path` to install elsewhere.
The installer verifies the archive against its attached SHA-256 file before
updating `$PREFIX/bin`.

## Compatibility and operator notes

- Runtime ABI remains v7 and the project version remains 0.2.0.
- The txiki.js and QuickJS upstream revisions remain unchanged.
- Configurations above 4096 static-pool workers are now rejected explicitly.
- A CORS origin list containing `"*"` must contain no other origin.
- Linux prebuilt installation currently supports x86_64/amd64 only; other
  architectures fail with an explicit message instead of downloading an
  incompatible package.

Each platform artifact includes the three command-line tools, the static C ABI
library, public headers, CMake package files, license, build identity, file
manifest, and SPDX SBOM. SHA-256 files are attached alongside every archive.
