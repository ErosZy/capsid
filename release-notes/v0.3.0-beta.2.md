# Capsid v0.3.0-beta.2

Experimental prerelease for evaluation, not a stable-production recommendation.
The runtime reports version 0.3.0; this distribution is explicitly beta.2.
Published 2026-11-17; latest stable remains v0.2.2. Product source is
87ed4630fa57e360ac0a3a8158218398250c8035. See the maintained
[current status](../docs/current-status.md) and [qualification record](../docs/v0.3.0-current-qualification.md).

Beta.1 was not published: its tag-triggered validation failed during Git
checkout before builds/tests. Its tag and failure logs are preserved. Beta.2
pins validation checkouts to the event commit SHA while retaining recursive
submodules, vendor tag policy, original test selections and budgets.

## Highlights

- First-party managed Host and expanded Fetch, streams, WebSocket, capability,
  lifecycle and cross-platform regression coverage.
- Compatible Headers normalization fast paths, with the non-ASCII/error paths
  preserved. Benchmark deployment readiness waits for the matching operation
  to commit before its single first business request.
- Host-only memory snapshots now cross an already-scheduled token-reclamation
  tick. This fixes pre-reclaim snapshots after cancellation; it does not add
  forced GC, relax memory assertions or extend cancellation/poison deadlines.
- Permanent pipelined cancellation/snapshot tests check all replies, natural
  exit, and that intentionally retained live allocations remain observable.
- Managed test backends keep the Host's kernel-selected listener owned for its
  lifetime. Discovery verifies child process identity and socket ownership,
  rather than selecting and releasing a supposedly unused port before bind.
- DNS/dial lifecycle probes wait for actual ACCEPT publication within the
  original observation window, rather than treating an earlier progress-phase
  callback as a command-queue barrier. Exact count/type and cleanup checks remain.

## Compatibility and limitations

- Public C ABI remains v7. FetchRPC defaults to v3 with explicitly negotiated
  additive v4/WebSocket support. No SDK/vendor upgrade is included in the final
  memory-snapshot fix. Recompile trusted bytecode for the matching identity.
- Linux strict sandboxing is the production isolation boundary. Native
  macOS/Windows and local non-isolated modes are for trusted code. Managed
  deployment interfaces remain experimental.
- App pidsMax is schema-recognized but not an effective per-App PID ceiling in
  this source; do not rely on it as an isolation control.
- Packages target Linux x86_64 musl, macOS arm64 and Windows x86_64 static CRT.
  Other target/platform combinations are not claimed by these release assets.
- CI uses the existing pinned workerd compatibility profile, not a claim of
  complete Web Platform Tests conformance. Five known raw WPT file failures
  and genuine prerequisite skips remain explicitly reported. In particular,
  Headers basic/errors, two promise-rejection files, and MessagePort initial
  disabled behavior remain compatibility limitations.
- Instrumented-memory acceptance is separate from production RSS qualification.
  Passing required CI gates does not close every historical failure cause or
  the complete v0.3.0 R1-R9 programme.
- Earlier accepted local performance evidence belongs to its frozen Headers
  source. It is not relabeled as a new measurement of this final snapshot fix.
  Historical v0.2.2 reference data has not been changed or rerun.

## Publication gate and installation

The exact frozen product passed full Release/LTO, ASan/UBSan/TSan, macOS,
Windows and fuzz CI (43881121477), same-source Debug and uninterrupted 1800-second
soak (43881141077), and three-platform package preflight (43881160382). Actual
tag validation/packages (43912740060) passed. Its never-acquired macOS package
job received exactly one authorized capacity retry and executed successfully
on attempt 2; the other ten executions retained their original attempt 1.

Seven assets and their remote digests were independently checked after
publication. The [final publication evidence](../docs/evidence/v0.3.0/2026-11-13-ci-resumption/beta2-publication-final-r1.json)
preserves cancellations/failures and actual source/job/asset identities.
Later documentation/data changes are not another binary qualification.

Install this beta explicitly (the default installer still selects stable):

```sh
curl -fsSL https://github.com/ErosZy/capsid/releases/download/v0.3.0-beta.2/install.sh | bash -s -- v0.3.0-beta.2
```

Each archive has a SHA-256 sidecar and carries build identity, the package file
manifest, C ABI headers and an SPDX SBOM. This prerelease must not become the
latest stable release.
