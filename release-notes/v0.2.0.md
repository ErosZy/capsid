# Capsid v0.2.0

Capsid v0.2.0 is the first stable release of the 0.2 line. It promotes the
final `v0.2.0-rc.07` implementation after completing the release-candidate
validation cycle. The runtime ABI remains at v7 and FetchRPC remains at v3.

## Highlights

- First-party `capsid-host` deployment service with single-worker and static
  pool modes, generation-based rollout, health monitoring, admission control,
  routing, CORS, and an administrative API.
- Binding v1 with trusted host packages, isolated QuickJS runtimes, bounded
  asynchronous RPC, neutral-value transport, capability policy enforcement,
  secret injection, and security audit events.
- Expanded web-platform support across Fetch, Streams, URL, Encoding, Blob,
  FormData, Web Crypto, Abort APIs, timers, console, and structured clone.
- Direct-fetch improvements including system DNS resolution, TLS, connection
  reuse, keep-alive pooling, streaming bodies, cancellation, and deterministic
  terminal cleanup.
- Validated compatibility lanes for Hono 4.12.32, itty-router 5.0.24,
  H3 2.0.1-rc.26, and Elysia 1.4.29.
- Release packages for Linux x86_64 musl, macOS arm64, and Windows x86_64,
  including the runtime, worker launcher, bytecode compiler, host, static
  library, public headers, CMake metadata, manifest, SBOM, checksums, and
  installer.

## Runtime And Web Platform

- The WinterTC ECMA-429 subset is available through the documented runtime
  surface and is exercised by the maintained WPT-derived suite.
- Module loading, bytecode validation, request dispatch, response streaming,
  task draining, and cancellation share explicit limits and terminal-state
  behavior.
- The maintained WPT path registry contains 84 paths, with coverage focused on
  the worker runtime and web-standard primitives rather than service bindings.
- Worker bundles can use the supported single-file module format and documented
  framework adapters without a Node.js runtime.

## Host And Binding V1

- `capsid-host` supports one worker or an arbitrary static pool from 1 to 4096
  workers, with per-worker concurrency and queue controls.
- Linux managed deployment includes generation staging, health gates,
  blue-green activation, rollback-oriented state, and artifact identity checks.
- Binding packages are host-authored and trusted. Each package runs in a
  separate QuickJS runtime and communicates with workers over the bounded
  Binding v1 protocol.
- Capability declarations, deny-by-default policy, trusted-bytecode
  attestation, secret handling, and audit records are part of the supported
  security model.

## Security And Isolation

- Linux strict mode combines process isolation with seccomp, Landlock,
  namespaces, resource limits, and cgroup controls where the host supports
  them.
- Network, filesystem, environment, and binding access remain explicit
  capabilities rather than ambient authority.
- macOS and Windows builds support local development and compatibility testing;
  Linux strict mode remains the production isolation target for this release.

## Performance Baseline

The stable release adopts the conclusion-level measurements collected from the
final `v0.2.0-rc.07` binary on a 4C/8T Ubuntu 24.04/WSL2 host:

| Scenario | Result |
| --- | ---: |
| JSON 1 KiB throughput | 7,261 requests/s |
| JSON 16 KiB throughput | 5,141 requests/s |
| Stream 1 KiB throughput | 4,845 requests/s |
| Serving memory | 5.9 MB PSS host, 6.4 MB per worker |
| 10 KiB bundle cold start | 8.34 ms source, 7.29 ms bytecode |

The measurements keep their final-RC artifact identity for provenance. See
`docs/performance-benchmarks.md` for commands, samples, variance, and known
measurement caveats.

## Compatibility And Upgrade Notes

- The public C ABI remains v7. Applications already targeting the v7 ABI do not
  need an ABI migration for this release.
- FetchRPC remains v3. It is a private host/worker transport and is not a
  Cloudflare Workers protocol compatibility guarantee.
- The first-party host configuration and administrative APIs are operational
  interfaces for the 0.2 line, but they are still pre-1.0 and may evolve in
  later minor releases.
- Capsid targets a focused worker runtime and web-platform surface. It is not a
  drop-in Node.js replacement, and Cloudflare service products such as R2 and D1
  are outside the current compatibility scope.
- The versioned path toward protocol-first WebSocket support, Binding RPC v2,
  module-worker semantics, and broader workerd compatibility is documented in
  `ROADMAP.md`.

## Install

Install the latest stable release:

```sh
curl -fsSL https://github.com/ErosZy/capsid/releases/latest/download/install.sh | bash
```

Install this exact release:

```sh
curl -fsSL https://github.com/ErosZy/capsid/releases/download/v0.2.0/install.sh | bash -s -- v0.2.0
```

Every archive is accompanied by a SHA-256 checksum. The installer verifies the
checksum before extracting files.
