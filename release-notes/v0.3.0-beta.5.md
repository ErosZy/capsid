# Capsid v0.3.0-beta.5

Experimental prerelease (runtime version `0.3.0`, public C ABI v7). Select
`v0.3.0-beta.5` explicitly; GitHub's default download and the stable
`v0.2.2` release are unchanged.

## Changes

- JavaScript hot-path optimizations for Fetch, URL parsing and request
  dispatch. Request and Response body consumers no longer share buffers with
  application streams; cloning a fixed byte body takes one independent
  snapshot without invoking `Symbol.species`.
- Ordinary Fetch, HTTP codec, WebSocket Upgrade, Upgrade Lifetime and Proxy
  fixtures bind both localhost loopback families. Windows validity runs retain
  per-case JSON evidence even on failure, without relaxing timing or
  behavioral checks.
- Native packages are available for fully static musl Linux (x86_64/ARM64),
  macOS (Apple Silicon/Intel) and Windows (x86_64 MSVC/static CRT).

## Install

Select the prerelease explicitly on Linux or macOS:

```sh
curl -fsSL https://github.com/rowanellis-113/capsid/releases/download/v0.3.0-beta.5/install.sh \
  | CAPSID_REPO=rowanellis-113/capsid bash -s -- v0.3.0-beta.5
```

On Windows, verify the ZIP against its `.sha256` sidecar and extract it to
a new directory. Do not mix the Host, worker, compiler or SDK across builds;
recompile trusted bytecode for the matching compatibility ID. See the
[installation guide](https://github.com/rowanellis-113/capsid/blob/dev/v0.3.0/docs/releases.md)
for OS/architecture selection and verification.

Linux strict sandboxing requires the documented kernel and delegation
prerequisites. Native macOS and Windows builds are for trusted development and
integration. The pinned compatibility profile retains five raw WPT file
failures; green CI is not full standards conformance. The archived
`0.3.0-beta.4` development measurement (`82eaab9`) does not measure this release.
