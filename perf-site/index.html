Why Capsid

Security without the V8 memory tax or MicroVM latency

Running untrusted user or AI-generated JavaScript usually forces an ugly trade-off: unsandboxed runtimes risk host compromise, V8 isolates balloon to hundreds of megabytes under load, and full containers stall cold starts. Capsid closes that gap at the runtime boundary.

01 / Hard OS Isolation

Default-deny Linux capsule

Every tenant runs in its own worker process fenced by Linux Namespaces, Landlock, and Seccomp. When egress_policy == NULL, all outbound network requests fail closed; tjs:*, FFI, and raw sockets cannot be enabled.

JIT RWX attack surfaceZero (QuickJS-NG)
02 / Scale-to-Zero

Sub-20 ms cold starts at 1 MiB

Precompiled QuickJS bytecode eliminates parse-time stalls as user scripts grow from 10 KiB to 1 MiB — waking isolated workers faster than V8, JSC, or containers with zero warm-up jitter.

No runaway multi-hundred-MiB JIT code cache. Under 64-connection load, Capsid's complete host + strict worker tree holds low-tens of megabytes, preserving 99%+ warm pool capacity.

Quick Start

Ship your first isolated worker in 30 seconds

Native prebuilt archives ship for Linux musl (x86_64, arm64), macOS (arm64, x86_64), and Windows (x86_64) — including capsid-host, capsid-worker, capsid-bytecode-compile, and the C/C++ SDK.

Production strict Linux sandboxing is Linux-only; native macOS & Windows builds are for trusted dev & SDK integration.
01Install binaries

Download & verify the native release

Downloads the prebuilt v0.3.0-beta.5 archive for your OS/CPU, verifies its SHA-256 sidecar, and unpacks capsid-host, capsid-worker, and capsid-bytecode-compile. Prefer manual/offline download? Grab any .tar.gz / .zip + .sha256 directly from Releases.

SHA-256 verifiedLinux · macOS · Windows

curl -fsSL \
  https://github.com/rowanellis-113/capsid/releases/download/v0.3.0-beta.5/install.sh \
  | CAPSID_REPO=rowanellis-113/capsid bash -s -- v0.3.0-beta.5
$base = 'https://github.com/rowanellis-113/capsid/releases/download/v0.3.0-beta.5'
$zip  = '.\capsid-0.3.0-windows-x86_64.zip'
Invoke-WebRequest "$base/capsid-0.3.0-windows-x86_64.zip" -OutFile $zip
Invoke-WebRequest "$base/capsid-0.3.0-windows-x86_64.zip.sha256" -OutFile "$zip.sha256"
$exp = ((Get-Content "$zip.sha256" -Raw).Trim() -split '\s+')[0]
$got = (Get-FileHash $zip -Algorithm SHA256).Hash
if ($got -ine $exp) { throw 'SHA-256 mismatch' }
Expand-Archive -LiteralPath $zip -DestinationPath "$HOME\capsid-beta" -Force
02Create app & policy

Write the ESM handler & capsid.json

Create a user-owned working directory (required by Capsid's ownership checks), save a UTF-8 self-contained fetch(req) handler, and declare a default-deny capsid.json with zero capability modules and zero outbound egress.

Zero bundler requiredDefault-deny policy
~/capsid-hello · app.bundle.js + capsid.json 
mkdir -p ~/capsid-hello && cd ~/capsid-hello

cat > app.bundle.js <<'EOF'
export default {
  fetch(req) {
    return Response.json({
      hello: "from Capsid",
      path: new URL(req.url).pathname,
    });
  },
};
EOF

cat > capsid.json <<'EOF'
{
  "apiVersion": "capsid/app-v1",
  "permissions": { "modules": [], "fetch": { "allow": [] } },
  "pool": { "minReady": 1, "maxWorkers": 1 }
}
EOF
New-Item -ItemType Directory -Force "$HOME\capsid-hello" | Out-Null
Set-Location "$HOME\capsid-hello"
$utf8 = New-Object System.Text.UTF8Encoding($false)

[IO.File]::WriteAllText("$PWD\app.bundle.js", @'
export default {
  fetch(req) {
    return Response.json({

    });
  },
};
'@, $utf8)

03Run & verify

Launch the Host & hit your endpoint

Start capsid-host in Terminal 1 (using --strict-sandbox off for local dev across Linux/macOS/Windows). Once stdout prints the capsid-host-ready-v1 JSON line, send a live HTTP request from Terminal 2.

Ready JSON on fd 1Path routing
Terminal 1 · Start Host 
~/.local/bin/capsid-host --mode single-worker \
  --worker ~/.local/bin/capsid-worker \
  --source-bundle ./app.bundle.js \
  --source-name "file://$PWD/app.bundle.js" \
  --application hello --listen 127.0.0.1:8080 \
  --routing path --public-scheme http \
  --public-authority 127.0.0.1:8080 \
  --request-timeout-ms 5000 --strict-sandbox off \
  --ready-fd 1 --capsid-json ./capsid.json
$hostExe = Get-ChildItem "$HOME\capsid-beta" -Recurse -Filter capsid-host.exe |
  Select-Object -First 1
$capsidBin = $hostExe.DirectoryName

$sourceName = ([System.Uri]$bundle).AbsoluteUri

04Optional · Production

Bundle npm deps & compile trusted bytecode

Apps with TypeScript or npm dependencies (Hono, itty-router) bundle ahead of time into one ESM file. For sub-20 ms cold starts on large bundles, precompile trusted QuickJS bytecode with the matching release's capsid-bytecode-compile and sign message.bin offline (see Host configuration).

Sub-20 ms 1 MiB cold startSigned attestation
~/.local/bin/capsid-bytecode-compile \
  --source ./app.bundle.js \
  --source-name "file://$PWD/app.bundle.js" \
  --application hello --version v1 --key-id release-key-1 \
  --bytecode-out ./bundle.qjsb \
  --attestation-out ./bytecode.json \
  --signing-message-out ./message.bin
& "$capsidBin\capsid-bytecode-compile.exe" `
  --source $bundle --source-name $sourceName `
  --application hello --version v1 --key-id release-key-1 `
  --bytecode-out .\bundle.qjsb `
  --attestation-out .\bytecode.json `
  --signing-message-out .\message.bin
npx esbuild src/index.ts \
  --bundle --format=esm --target=es2022 \
  --outfile=app.bundle.js
