# H3 v2 兼容性

## 状态

Capsid Runtime 验证固定的 **H3 2.0.1-rc.26**，版本和完整性由
`examples/h3-v2-reference/package.json` 与 lockfile 固定。它不代表其他 RC
或未来 H3 v2。

reference build 生成七个受审计 ESM：五种入口，以及 malformed URL 和 debug
fixture。每个输出必须为单文件、零 external/dynamic import，不含 source map、
Node built-in、`file:`、`require`、platform global、H3 Node adapter、srvx
listener 或 server implementation；大小上限为 192 KiB。

## 构建与验证

```sh
npm ci --ignore-scripts --prefix vendor/txiki.js
npm ci --ignore-scripts --prefix examples/h3-v2-reference

cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build --target \
  test-h3-v2-worker-driver test-module-denial test-p0-integration
ctest --test-dir build --output-on-failure \
  -R '^(worker_h3_v2_|worker_p0_contract$)'
```

129 个确定性向量在同一 bundled H3 应用的 Node reference 与真实 worker 间
比较，并带独立绝对断言。

## 已验证

- H3 app、`{ fetch }`、named/wrapper/standalone handler 入口；
- `on`、method shortcut、`all`、`use`、`register`、`mount`、`fetch`；
- route、params/query、Unicode、malformed URL 策略；
- H3Event、request-local context、middleware 和 hooks；
- JSON/text/urlencoded/multipart/File/ArrayBuffer/stream request；
- object/string/binary/Blob/File/BigInt/Promise/stream/redirect response；
- prepared status/status text/header 和有序的多个 `Set-Cookie`；
- error redaction、debug stack、hook failure 与 worker 复用；
- nested app、`fromWebHandler`、cookies、CORS、auth、validation、session、
  cache、proxy、内存 static 和 SSE/EventStream；
- plugin、lazy init、`onDispose`、direct fetch、permission、cancel、timeout；
- 196,645-byte 双向 stream 跨多个 1 KiB FetchRPC credit window。

差分比较 status/status text、普通 header、有序 `Set-Cookie`、精确 body 和
stream aggregate、route/context/trace，以及 error/prepared-response 行为。
只归一化动态 `Date`、生成的 session value 和 transport chunk 数；cookie
attribute/order、总长度和 checksum 仍必须精确。

## 支持与排除

支持 H3 Core 和文中已验证的 runtime-neutral、Web-standard utility。宿主仍
负责 server、pool、timeout、网络与 sandbox；“支持”不代表未列出的所有 export
或 option 都已验证。

明确排除：

- `h3/node`、Node handler/built-in；
- `serve()`、srvx listener/server；
- `crossws/server` 与 WebSocket server/upgrade；
- Bun、Deno、Cloudflare、Lambda 等 adapter；
- 真实文件系统 static serving；
- external/remote/network/`file:` module loading；
- process/worker creation、ambient fs、txiki private API；
- host-backed `event.waitUntil` 生命周期扩展。

八个 `h3-v2-excluded` 测试维护这些边界。H3 的 `event.waitUntil()` convenience
method 因宿主没有对应 lifetime hook，被明确列为 Excluded。

兼容工作只修复通用 runtime 行为：status text、多个 `Set-Cookie` 顺序和取消
后的有界 tombstone draining；runtime 源码未加入 H3 名称或私有 shim。

## 升级流程

更新精确依赖和 lockfile 后，重建/审计七个 bundle，并运行 differential、
lifecycle、permission、excluded-import、global-surface、P0 与 sanitizer
矩阵。新的 srvx/rou3 输入、global、normalization 和 exclusion 必须显式审查。
